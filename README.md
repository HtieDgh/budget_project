# Расчет экономической целесообразности проекта методом линейной интерполяции

Это личный инструмент для предсказания остатка бюджета на основе текущего среднего значения расхода. Использует линейную интерполяцию для ответа на вопрос "А хватит ли мне денег при текущей скорости расхода денег из бюджета?". Результат работы программы не обладает банковской точностью, а служит лишь дополнительным инструментом перед принятием решения о изменении стратегии расхода бюджета.

## Структура репозитория

| Директория | Описание | Содержимое |
|:---|:---|:---|
| `budget/` | Основной исходный код | Модели и контроллеры |
| ├─ `Models/` | Модели данных | Модель данных Expense |
| ├─ `Services/` | Сервисы | Набор классов реализующих бизнес-логику проекта |
| └─ `Shared/` | Общие вспомогательные классы | Прочие классы, не реализующие бизнес-логику |
| `README.md` | Текущий файл | Документация проекта |

## Запуск программы

Описание опции можно получить:
```
budget --help
```

Использование:

```
budget -s 2026-09-01 -e 2026-10-01 -b 15000
```

### Особые возможности: 

#### ВВОД расходов со скриншотов из банка с помощью OCR

Разработан метод парсинга данных из скриншотов истории Сбера, чтоб не вводить csv файлы вручную. Это должно упростить учет текущего расхода бюджета. Чтобы воспользоваться такой возможностью необходимо:

* Скачать Языковые данные: необходимо скачать файл rus.traineddata (для русского) из официального [репозитория](https://github.com/tesseract-ocr/tessdata/blob/main/rus.traineddata) и положить его в папку `.tessdata/`. Файл должен присутствовать при запуске программы.
* Теперь достаточно скинуть скрины в директории и указать путь до нее:

```
budget --from-images /path/to/img/dir -s 2026-09-01 -e 2026-10-01 -b 15000
```

#### ВВОД расходов под диктовку

Разработан метод парсинга данных из текста надиктованного с микрофона. На данный момент считывается звук с текущего микрофона по умолчанию на пк. Например, пусть диктовка будет такой:

```
девятое сентября восемь девять девять запятая один один восьмое сентября три восемь девять шесть запятая девять ноль шестое сентября шесть семь четыре
```

Команда (опция `--voice` указывает что используется голосовой ввод):

```
budget -s 2026-09-01 -e 2026-10-01 -b 11369.74 --voice
```

## Сборка

Для корректной сборки локально должны присутствовать директории `.tessdata` и `.voice_models`, а в этих директориях соответствующие модели. Требуется:

* (rus.traineddata)[https://github.com/tesseract-ocr/tessdata/blob/main/rus.traineddata] - скачать и поместить в папку `.tessdata`. Должно получится `.tessdata/rus.traineddata`
* (vosk-model-small-ru-0.22)[https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip] - разархивировать и поместить содержимое в папку `.voice_models`. Должно получится `.voice_models/vosk-model-small-ru-0.22/`

Эти пути поместите в конфиг, информация о нем представлена ниже.

### Настройка проекта

При разработке чувствительные данные были сохранены в отдельный файл по пути `/budget/.venv/config.json`, который не отслеживается системой контроля версий. Этот файл необходим для запуска, убедитесь что он существует по заданному пути. Его структура представлена ниже:

```json
{
  "Expense": {//Расход
    "Path":"\\csv\\expense.csv",
    "HeaderShema": [ "Sum", "Date", "Category" ],
    "DateFormats": [ "yyyy-MM-dd" ],
    "MaxPossibleStrategies":30
  },
  "Options": {//Настройки аргументов командной строки
    "DateFormats": [ "yyyy-MM-dd" ]
  },
  "OCRReader":{//Настройки OCR ридера
    "DefaultTessdataDirectory":"\\path\\to\\.tessdata\\"
  },
  "VoiceReader":{//Настройки голосового ввода
    "DefaultVoiceModelDirectory":"\\path\\to\\.voice_models\\",
    "CurrentLanguageModel":"vosk-model-small-ru-0.22\\"
  }
}
```

> [!IMPORTANT]
> Все ключи должны присутствовать. Комментарии следует убрать.

Также из индекса убран `/budget/Properties/launchSettings.json`, если он необходим, то создайте его:

```json
{
  "profiles": {
    "budget": {
      "commandName": "Project",
      "commandLineArgs": "--help"
    },
    "budget today": {
      "commandName": "Project",
      "commandLineArgs": "-s 2026-09-01 -e 2026-10-01 -b 15000"
    }
  }
}
```

Иначе можно просто вызвать `dotnet run <опции командной строки>` из корня проекта.
